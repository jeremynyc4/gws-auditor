Google Workspace Security Auditor — Installation

This page covers the one-time software installation required before you can run audits. Once complete, you will not need to repeat these steps.

Before you begin: These steps require downloading and installing software. You will need an internet connection, and your computer's security software may ask you to confirm each installation — click Yes or Allow when it does.

Part 1 — Install Python

Python is a programming language the audit tool is written in. Even if you are not a programmer, you need it installed for the tool to run.

  1. Open your browser and go to:
    https://www.python.org/downloads/
  2. Click the large yellow Download Python button. The file will be named something like python-3.x.x-amd64.exe.
  3. Once downloaded, open the file to start the installer.
  4. Important: On the first screen of the installer, check the box that says "Add Python to PATH" before clicking anything else. This box is near the bottom of the screen and is not checked by default.
  5. Click Install Now and wait for it to finish.
  6. Click Close when the installer is done.

To confirm it worked:

  1. Press the Windows key, type PowerShell, and press Enter.
  2. In the window that opens, type the following and press Enter:
python --version

You should see a version number printed (e.g., Python 3.12.4). If you see an error, close and reopen PowerShell and try again.

Part 2 — Install the Google Cloud CLI

The Google Cloud CLI (also called "gcloud") is a tool that lets your computer communicate securely with Google's systems. The audit tool uses it to set up access to your Google Workspace domain.

  1. Open your browser and go to:
    https://cloud.google.com/sdk/docs/install
  2. Under the Windows section, click the link to download the installer (it will be a file ending in .exe).
  3. Open the downloaded file and follow the installer prompts, accepting the defaults on each screen.
  4. On the final screen, leave the checkboxes as they are and click Finish. A terminal window will open briefly — this is normal.
  5. Close and reopen PowerShell so it picks up the newly installed tool.

To confirm it worked:

  1. In a new PowerShell window, type the following and press Enter:
gcloud --version

You should see version information. If you see an error, restart your computer and try again.

Part 3 — Download the Audit Tool

  1. In PowerShell, navigate to the folder where you want to store the tool. For example, to put it in your Projects folder:
cd C:\Users\YourName\Projects

(Replace YourName with your actual Windows username.)

  1. Download the tool by running:
git clone https://github.com/argusssec-cloud/gws-auditor.git
  1. Move into the newly downloaded folder:
cd gws-auditor
  1. Create an isolated workspace for the tool's dependencies:
python -m venv .venv
  1. Activate that workspace:
.venv\Scripts\activate

You will know it worked when you see (.venv) at the start of the line in PowerShell.

  1. Install the tool and its dependencies:
pip install -e .

This may take a minute or two. When it finishes you will see a line that says Successfully installed.

Note: Every time you open a new PowerShell window to run an audit, you will need to navigate back to this folder and re-run step 5 (the .venv\Scripts\activate command) before doing anything else.

Google Workspace Security Auditor — Running an Audit

Follow these steps each time you want to set up and run an audit for a domain. You will repeat this process for each domain you audit.

Before you begin each domain: Make sure you know which browser profile you use for that domain's admin account. For example, if you manage acme.com in Chrome and otherdomain.com in Edge, you will need the right browser open and signed in at the right points in these steps.

Part 1 — Prepare PowerShell

  1. Open PowerShell (press the Windows key, type PowerShell, press Enter).
  2. Navigate to the audit tool folder:
cd C:\Users\YourName\Projects\gws-auditor

(Replace YourName with your actual Windows username.)

  1. Activate the tool's workspace:
.venv\Scripts\activate

You will see (.venv) at the start of the line when this is active.

Part 2 — Sign In to Google Cloud

The setup script needs to sign in to Google Cloud on behalf of this domain's admin account. Because you may have multiple Google accounts across different browsers, these sign-in steps give you a link to paste into the correct browser rather than opening one automatically.

Step 2a — Standard sign-in

  1. In PowerShell, run:
gcloud auth login --no-launch-browser
  1. PowerShell will display a long URL. Copy the entire URL.
  2. Open the browser that is signed into this domain's admin account and paste the URL into the address bar.
  3. Sign in if prompted, then click Allow.
  4. Google will show you a verification code. Copy it and paste it back into PowerShell, then press Enter.

Step 2b — Application credentials sign-in

This is a second, separate sign-in that the tool also requires.

  1. In PowerShell, run:
gcloud auth application-default login --no-launch-browser
  1. Repeat the same process: copy the URL, paste it into the correct browser, sign in, copy the verification code, paste it into PowerShell.

Part 3 — Run the Setup Script

This script does the technical work of setting up a Google Cloud project and preparing the audit tool to access your domain. It takes about one to two minutes to complete.

  1. In PowerShell, run the following, replacing the example values with your actual domain name and admin email address:
python scripts/setup_domain.py yourdomain.com admin@yourdomain.com

For example, for a domain called acme.com:

python scripts/setup_domain.py acme.com admin@acme.com

The script will display progress as it works. When it finishes, it will print a section that looks like this:

====================================================================== MANUAL STEP REQUIRED: Domain-Wide Delegation ====================================================================== Client ID: 108603865820338527706 OAuth scopes: https://www.googleapis.com/auth/admin.directory.domain.readonly,...

Leave this PowerShell window open. You will need the Client ID number and the OAuth scopes text in the next step.

Part 4 — Grant Access in the Google Admin Console

This is the one step that cannot be automated. It tells Google that the audit tool has permission to read security data for your domain.

  1. Open the browser that is signed into this domain's admin account and go to:
    https://admin.google.com
  2. In the left-hand menu, click Security.
  3. Click Access and data control, then API controls.
  4. Click Manage Domain Wide Delegation.
  5. Click Add new.
  6. In the Client ID field, paste the number printed by the script in Part 3 (e.g., 108603865820338527706). The number will be different for each domain.
  7. In the OAuth scopes field, paste the long line of text printed by the script. It begins with https://www.googleapis.com/auth/admin.directory… and continues without line breaks.
  8. Click Authorize.
If a dialog asks whether to overwrite an existing entry: Click Yes only if the Client ID shown matches the number the script just printed. If the numbers are different, click Cancel and contact your administrator.

Part 5 — Wait for Google to Activate the Access

After clicking Authorize, Google takes up to 15 minutes to apply the change. You do not need to do anything during this time — you can move on to other work and come back.

Part 6 — Run the Audit

  1. Return to the PowerShell window from earlier (with (.venv) showing).
  2. Run the audit, replacing yourdomain.com with the actual domain:
python -m gws_auditor --config domains/yourdomain.com/config.yaml

For example:

python -m gws_auditor --config domains/acme.com/config.yaml

The audit runs for several minutes. When it finishes, it displays a summary and saves the results to a reports folder.

If you see "unauthorized_client" errors: The 15-minute activation period from Part 5 has not finished yet. Wait a few more minutes and run the command again.

Part 7 — Open the Report

  1. Open File Explorer and navigate to:
C:\Users\YourName\Projects\gws-auditor\domains\yourdomain.com\reports
  1. You will see one or more files with names that include today's date. Open the file ending in .html — it will open in your browser as an interactive report.

Part 8 — Before Your Next Audit of This Domain

As a security measure, the audit tool automatically deletes the key file it uses to access your domain once the audit is complete. This means you need to generate a new one before running the audit again.

  1. Open your browser and go to:
    https://console.cloud.google.com
  2. At the top of the screen, click the project dropdown and select the project for this domain (it will be named something like yourdomain-com-audit).
  3. In the left-hand menu, click IAM & Admin, then Service Accounts.
  4. Click on the service account named gws-auditor.
  5. Click the Keys tab.
  6. Click Add Key → Create new key → JSON → Create.
  7. A file will download automatically. Move it into:
    C:\Users\YourName\Projects\gws-auditor\domains\yourdomain.com\credentials\
  8. Open the file config.yaml in that domain's folder in a text editor (right-click → Open with → Notepad), and update the line that starts with credentials_file: to match the new filename.
  9. You are now ready to run Part 6 again.
Tip: Alternatively, you can skip steps 1–8 above and re-run the setup script from Part 3. It will detect that the project and service account already exist and only create a new key file and update your config automatically.
